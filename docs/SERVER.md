# Подготовка сервера

Приложению нужен только стандартный SSH-проброс (`ssh -D`): оно подключается к серверу и открывает
каналы `direct-tcpip`, оболочку и команды не запускает. Поэтому для него удобно завести отдельного
пользователя, который умеет только пробрасывать TCP.

## Скрипт `server/sshtunnel-user.sh`

```bash
curl -fsSLO https://raw.githubusercontent.com/usmanec/sshtunnel/main/server/sshtunnel-user.sh
sudo bash sshtunnel-user.sh          # меню: добавить/изменить, удалить, список
sudo bash sshtunnel-user.sh add      # сразу к нужному шагу (add | remove | list)
```

Можно и одной командой: `curl -fsSL <тот же адрес> | sudo bash`. Вопросы читаются из терминала,
но скачанный файл удобнее проверить перед запуском. Язык выбирается по `LANG`, его можно задать
явно: `SSHTUNNEL_LANG=ru|en`.

Скрипт спрашивает:

1. **Имя пользователя.** Существующих пользователей системы скрипт не меняет, только тех, кого
   создал сам (группа `sshtunnel`).
2. **Способ входа** — такие же варианты, как в поле «Тип» в приложении:
   - приватный ключ (рекомендуется);
   - пароль;
   - ключ + пароль: сервер требует оба (`AuthenticationMethods publickey,password`).
3. **Ключ.** Его можно создать на сервере (ed25519, по желанию с паролем ключа; приватный ключ
   выводится один раз и на сервере не остаётся) или вставить готовый публичный ключ.
4. **Пароль** — случайный или свой.
5. **Разрешённые адреса.** Пусто — любые, как у обычного `ssh -D`. Можно перечислить `хост:порт`
   (`PermitOpen`). Приложения подключаются по IP, поэтому нужны IP-адреса. Подсети `PermitOpen` не
   поддерживает. К списку автоматически добавляется `DNS-сервер:53` из настроек приложения: DNS идёт
   через тоннель. Карточка внешнего IP на главной в этом режиме не определит адрес.

В конце скрипт выводит данные для формы сервера в приложении и команду для проверки с компьютера.

## Что получает пользователь

- Оболочка `nologin`, `ForceCommand nologin`, `PermitTTY no`: ни входа, ни команд, ни SFTP/SCP.
- `AllowTcpForwarding local`: только прямой проброс, без `-R`; `GatewayPorts no`.
- Без проброса агента, X11, Unix-сокетов и `tun` (`PermitTunnel no`), без `~/.ssh/rc`.
- Ключи в `authorized_keys` с опциями `restrict,port-forwarding`.
- Если пароля нет, пароль в `/etc/shadow` — `*`: учётная запись не заблокирована (иначе sshd без PAM
  отказывает во входе), но пароль не подходит никакой.

Настройки лежат в отдельном блоке `Match User <имя>`:

- **OpenSSH 8.2+ с `Include /etc/ssh/sshd_config.d/*.conf`** (Debian 11+, Ubuntu 20.04+ и др.) —
  в файле `/etc/ssh/sshd_config.d/00-sshtunnel-<имя>.conf`. Match в подключённом файле не
  распространяется на основной конфиг.
- **Иначе** — в конце `/etc/ssh/sshd_config` между маркерами `# BEGIN/END sshtunnel <имя>`.

Перед изменением скрипт проверяет текущий конфиг (`sshd -t`), после изменения проверяет снова и при
ошибке всё откатывает. Затем перезагружает sshd: systemd, OpenRC, `service` или `HUP`. Если в sshd
заданы `AllowUsers`/`AllowGroups`, скрипт предупредит: туда нужно добавить нового пользователя.

## Проверено

На OpenSSH 9.6 (Ubuntu 24.04):

- `-D` работает, `PermitOpen` пропускает только перечисленные адреса;
- вход в оболочку, PTY, SFTP и `-R` отклоняются;
- «ключ + пароль» не пускает только с ключом;
- для `root` и других пользователей настройки не меняются;
- после удаления пользователя `sshd_config` побайтно совпадает с исходным.
